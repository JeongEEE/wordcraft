# Word 포크 구현 계획

설계: `docs/superpowers/specs/2026-11-18-word-fork-design.md`.
참조 구현: `/Users/jeong/Dev/MyProjects/gridcraft` 의 `my-custom` 브랜치(Grid 포크).
`git -C ../gridcraft diff main...my-custom -- <경로>` 로 Grid 포크가 원본에서 바꾼 부분을 보고,
wordcraft의 현재 코드에 맞춰 옮긴다. Grid 전용 기능(IME, 창 위치, 리본, 아랍어 테스트, 번역 보강)은 옮기지 않는다.

공통 규칙
- 브랜치 `my-custom`. Task마다 리뷰 통과 후 그 Task 경로만 스테이징해 한국어 Conventional Commit.
- crate·패키지 이름과 명령 ID는 유지. 사용자에게 보이는 이름·설치 식별자만 `Word`로 분리.
- Never crash 규칙(`unwrap`·`expect`·`panic` 금지)과 `cargo fmt`·`clippy -D warnings`를 지킨다.
- 개인키를 읽거나 만들지 않는다. 테스트는 결정적 테스트 키만 쓴다.
- 빌드: `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, cargo는 `~/.cargo/bin/cargo`.

## Task 3b: macOS 제목줄 끌어 창 이동 (참조: Grid `4acef33e`, `b4880333`, 소유자 요청 2026-11-18)
- [ ] macOS에서 `ViewportCommand::StartDrag`가 동작하지 않는다(winit 포크가 제목줄 기본 이동을 막고, StartDrag는 프레임 뒤에 처리돼 mouse-down을 놓침). Grid처럼 macOS에서는 드래그 중 포인터 이벤트가 있는 프레임마다 `OuterPosition`으로 창을 옮겨 누른 지점을 포인터 아래에 둔다. 누른 위치는 드래그 시작 때 저장(놓는 프레임에 egui가 지움), 움직임 판단은 `delta()`가 아니라 PointerMoved 이벤트 유무. Windows·Linux는 StartDrag 유지.
- [ ] 적용 지점: 메인 제목줄(`chrome.rs`), 백스테이지(`backstage.rs`), 같은 문제가 있는 대화상자 제목줄(`dialogs/chrome.rs`, 별도 viewport면 그 viewport 기준). 같은 로직은 한 곳에 두고 재사용.
- [ ] 회귀 테스트: Grid `tests/it/title_bar_drag.rs`처럼 창이 이동 명령대로 옮겨지는 모델로, 일정한 속도로 끌 때 매 이동마다 따라오는지·놓는 순간 이동까지 확인.
